## Behavior and limits

An ordinary full or incremental save preserves an existing `/ID`. Redaction, removal of hidden
information and sanitizing request a full rewrite with a new identifier. For encrypted documents,
the first identifier remains because the encryption key depends on it; the second changes. The
writer supports caller-provided entropy for reproducible tests. Otherwise it mixes host entropy:
native random hash seeds and a counter, or browser Web Crypto with a Math.random fallback.
The identifier is not a cryptographic digest or an anonymization guarantee.

Existing headless tools expose all three corrections: `action_run`, `redact_apply`,
`doc_remove_hidden`, `pdfa_verify` and `pdfa_convert`. Additional end-to-end tests cover
undo/redo, save/reopen, unchanged source files, subsequent ordinary saves and both passwords of
an encrypted sanitized copy. PDF/A checks and conversion remain partial, as recorded in parity;
no external validator result is claimed. The batch change propagates editing-step errors;
it does not change the separate JavaScript step's reporting policy.

## Validation

Validation uses Windows x64, the local Rust 1.95 toolchain, existing craft-fonts and pinned
craft-i18n build inputs. Cargo builds, tests and Clippy use `--locked` and two jobs.

- Before changing production code, the imported regressions reproduced five failures: two
  batch-error cases, two redaction/sanitizing identifier cases and the forbidden PDF/A annotation.
- COS, redaction and preflight suites: 406 passing tests, three pre-existing ignored tests.
  These include RC4, AES-128 and AES-256 identifier/password round trips, missing and malformed
  identifiers, all written bytes contributing to identifiers, deterministic entropy and fresh
  identifiers across processes.

- The complete automation integration binary: 338 passing tests, including all four original
  batch regressions and four additional copy/PDF/A save/reopen tests.
- PDF/A UI integration group: three passing tests, including the new real-panel conversion and
  verification test. The new message explicitly identifies the result as internal checks.
- The original standards-wording unit regression also passes: 748 passing tests in this batch
  overall, with the three pre-existing ignored tests above.
- COS compiles for `wasm32-unknown-unknown`. Browser Web Crypto/Math.random calls were not run
  in a browser; the pure fallback mixing and hash formula run in the native COS tests.
- Formatting, dependency layering, asset attribution and parity gates pass. In this exported
  directory the asset gate uses the existing index at `target/build-tools/asset-index.git`.

- Scoped Clippy passes with `--all-targets -- -D warnings` for COS, redaction, preflight,
  engine, automation and ui-egui.
- A native development build of `pdfcraft` and `pdfcraft-cli` succeeds. This batch does not
  rebuild release binaries or repackage the installer/portable ZIP.
- The updated CLI passes a confined 19-step script on synthetic files: redaction, ordinary and
  sanitized saves, PDF/A conversion and verification after reopen, and an intentionally failing
  batch step. Additional script assertions check new/stable identifiers and an empty output
  folder for the failed batch. Before/after and converted-page renders were visually inspected;
  only the marked word disappears and the neighboring text stays readable.
- The updated desktop app was launched with opt-in `--control`, an isolated portable profile
  and system fonts disabled. `pdfcraft-cli ui` opened the PDF/A panel, ran Verify and inspected
  the real result. The screenshot was visually checked; the full internal-check message fits
  the panel. The preview was closed without changing the user's settings or documents.
- `adapted.patch` passes `git apply --reverse --check`; `changed-files.json` records the
  before/after SHA-256 values. Both remain beside the source backup and logs under `target/`.
